StudyDesk 사용 설명서

이 앱의 목적

열자마자, 공부한 내용을 바로 적는다. StudyDesk의 모든 화면과 기능은 이 한 문장을 기준으로 만들고 판단합니다. 새 기능이나 디자인 변경은 "첫 글자를 쓰기까지의 탭 수가 줄어드는가"로 가치를 재며, 그렇지 않은 변경(장식, 색상 테마 등)은 뒤로 미룹니다.

  • 첫 화면은 종이 — 앱을 열면 마지막에 쓰던 노트북의 그 페이지가 다시 열립니다(기기별로 기억). PC에서는 커서가 이미 MAIN NOTES에 있어 바로 타이핑하면 되고, 폰에서는 종이가 맨 위에 오고 노트북 목록·오늘 목록·통계는 그 아래에 있습니다(상단 노트북 목록 버튼으로 목록까지 내려갑니다). 백업·주소 안내 띠는 화면 아래에 붙어 종이를 밀어내지 않습니다.
  • 손이 덜 가게 — 입력 즉시 자동 저장, 새 페이지의 날짜 자동 입력, 글이 넘치면 자동으로 다음 페이지, 일정에서 노트 열기 한 번으로 해당 노트북의 오늘 페이지.
  • 코넬 노트 그대로 — CUE(핵심 질문) | MAIN NOTES(본문) | SUMMARY(요약) 구조와 셀프 테스트(본문 가리고 회상) 복습 단계를 종이와 같은 형태로 둡니다.
  • 내 데이터는 내 것 — 기본은 이 브라우저에만 저장, 백업 파일은 열린 JSON, 기기 간 동기화는 선택이며 본인 계정 공간에만 저장됩니다.

StudyDesk란?

StudyDesk는 코넬(Cornell) 노트 필기법을 기반으로 한 개인 공부 노트 앱입니다. 강의, 독서, 자습 등 여러 활동을 과목별 노트북으로 나누어 기록하고, 학습 일정과 노트를 연결해 "오늘 공부할 것"에서 클릭 한 번으로 필기를 이어갈 수 있도록 설계되었습니다.

  • 설치 없음 — 브라우저에서 바로 실행됩니다. 별도 프로그램 설치나 회원 가입이 필요 없습니다.
  • 데이터는 기본적으로 내 브라우저에만 — 로그인하지 않으면 모든 노트는 이 브라우저 안(localStorage)에만 저장되고 어디로도 전송되지 않습니다. 설정 → 계정 탭(클라우드 동기화)에서 Google 계정으로 로그인하면 본인만 접근할 수 있는 클라우드 공간(Firebase)에 복사되어 다른 기기와 동기화됩니다.
  • 필기 흐름 자동화 — 새 페이지를 만들면 날짜가 자동 입력되고, 필기가 페이지를 넘치면 다음 페이지가 자동으로 생성되며, 일정의 노트 열기 버튼으로 해당 노트북의 오늘 쓸 페이지가 바로 열립니다.

페이지별 기능

노트북
메인 화면입니다. 코넬 노트 편집기, 노트북 목록·검색·필터, 오늘의 공부 목록이 모여 있습니다. 열면 마지막에 쓰던 노트북의 그 페이지가 열립니다. (아래 상세 참고)
자료실
공부한 자료(책·영화·인강·논문·음악 등)의 카탈로그입니다. 제목 검색으로 정보를 자동으로 채우고, 상태(예정 / 진행 중 / 완료)와 진행률·별점을 관리하며, 노트 열기로 해당 자료의 노트북과 연결할 수 있습니다. (아래 상세 참고)
달력
한 달 달력에 반복 일정과 단발 일정이 표시됩니다. 날짜의 +N개 더를 누르면 그날의 전체 일정과 노트 열기 버튼이 나옵니다.
일정 관리
반복 일정(요일 선택)과 단발 일정(날짜 지정)을 등록·삭제합니다. 모든 일정에 과목(subject)과 활동 유형(type)을 붙여 노트북과 연결합니다. (아래 상세 참고)
암기 카드
과목별 암기 카드를 만들고 복습 모드로 복습합니다. 카드를 클릭하면 앞/뒤가 뒤집히고, Esc 키나 닫기로 닫습니다.
설정
탭 여섯 개로 나뉘어 있습니다. 백업(백업 파일 백업 받기·백업 불러오기, 백업 알림 주기, 저장 공간 사용량. 맨 아래 빨간 테두리 안에 전체 데이터 삭제) · 계정(클라우드 동기화, 기기 간 동기화) · 화면(글꼴 손글씨 / 깔끔한 고딕, 노트 글자 크기, 언어) · 목록(과목, 자료실 카테고리·장르 목록 관리. 아래 "목록 탭" 참고) · 연동(자동 채우기 키, 구글 캘린더 가져오기) · 설명서(이 설명서). 마지막에 본 탭을 기억합니다. (아래 "데이터 보관" 참고)

코넬 노트 작성 자세히

노트북 하나는 "한 과목의 한 활동"을 담습니다. 예를 들어 economics 과목이라도 강의 노트(lecture)와 독서 노트(book)는 서로 다른 노트북입니다.

고정 정보 — 노트북을 만들 때 한 번 정합니다
과목, 종류(강의 / 책 / 영화 / 프로젝트 / 자습 / 기타), 주제(노트북 이름)
페이지별 정보 — 공부한 날마다 바뀝니다
챕터 / 소제목(그날 다룬 챕터), 태그 / 키워드(키워드), 날짜(새 페이지 생성 시 오늘 날짜가 자동 입력). ▶나 넘침으로 이어지는 새 페이지는 앞 페이지의 챕터·태그를 그대로 이어받습니다(고치거나 비워도 됩니다).

본문은 코넬 노트의 3구역 구조입니다. 왼쪽 CUE에 복습용 질문·키워드를, 오른쪽 MAIN NOTES에 본 필기를, 아래 SUMMARY에 요약을 적습니다.

  • 서식 도구 — MAIN NOTES 위 도구줄에서 굵게·기울임·형광펜·글자색(검정/빨강/파랑)·들여쓰기·라벨·링크·이미지를 사용할 수 있습니다. 폰에서는 자주 쓰는 굵게·형광펜·들여쓰기·이미지만 한 줄로 보이고, 맨 오른쪽 ⋯을 누르면 나머지(기울임·글자색·라벨·링크)가 한 줄 더 펼쳐집니다(기기별로 기억).
  • 마크다운 단축 입력 — **굵게**, *기울임*, ==형광펜==을 입력하면 즉시 서식으로 바뀝니다.
  • 이미지 — 이미지 버튼으로 파일을 선택하거나, 복사한 이미지를 Ctrl+V로 바로 붙여넣을 수 있습니다. 큰 이미지는 저장 공간 보호를 위해 자동으로 축소됩니다(긴 변 1280px).
  • 페이지 넘기기 — 노트 좌우의 ◀ ▶ 화살표로 이동합니다. 화면이 좁을 때(폰, 분할 화면 등)는 화살표가 종이를 가리지 않도록 노트 맨 아래 페이지 번호(1 / 3) 양옆으로 옮겨집니다. 마지막 페이지에서 ▶를 누르면 새 페이지가 만들어집니다. 필기가 화면을 넘치면 자동으로 다음 페이지가 생성됩니다. PC에서 가득 채운 페이지를 폰처럼 좁은 화면에서 열면 한 화면에 다 안 들어갈 수 있는데, 이때는 MAIN NOTES 안을 위아래로 스크롤하면 나머지 줄이 보입니다(내용은 잘리지 않습니다). 폰에서는 종이 아래의 하단 바(◀ 쪽수 ▶ · 저장)가 화면 아래에 붙어 있어 키보드가 올라와 있어도 스크롤 없이 페이지를 넘길 수 있습니다.
  • 페이지 바로 이동 — 하단의 페이지 번호(N / M)를 클릭하면 전체 페이지 목록(챕터·날짜·미리보기)이 열리고, 원하는 페이지로 바로 이동할 수 있습니다. 내용은 썼는데 SUMMARY가 비어 있는 페이지에는 요약 없음 표시가 붙고, 목록 위에 요약 없는 페이지 N개와 이것만 보기 버튼이 나옵니다. 코넬 복습 때 요약을 아직 안 쓴 페이지만 골라 돌아가기 좋습니다(빈 페이지는 표시하지 않습니다).
  • 셀프 테스트 (복습 모드) — 하단의 셀프 테스트 버튼(폭이 좁은 폰에서는 눈 아이콘만 보임)을 누르면 MAIN NOTES가 흐려져 가려집니다. 왼쪽 CUE의 질문·키워드만 보고 내용을 스스로 떠올려 보세요 — 코넬 필기법의 핵심 복습 단계입니다. 노트 보기를 누르면 다시 보입니다.
  • 저장 — 입력하는 즉시 자동 저장됩니다. 저장 버튼은 저장 상태를 확인하는 용도입니다.

일정과 노트 연결하기 (추천 워크플로우)

  1. 일정 관리에서 반복 일정을 등록합니다. 예: 제목 "economics 101 lecture", 과목 economics, 유형 lecture, 요일 월·수·금.
  2. 해당 요일이 되면 노트북 페이지의 오늘의 공부 목록에 그 일정이 자동으로 나타납니다.
  3. 공부를 시작할 때 일정 옆의 노트 열기 버튼을 누릅니다. 그 과목·유형의 노트북이 오늘 쓸 페이지로 열립니다: 마지막 페이지가 이미 오늘 날짜이거나 비어 있으면 그 페이지, 아니면 그 뒤에 오늘 날짜의 새 페이지(챕터·태그는 앞 페이지에서 이어받음)가 생깁니다. 지난 필기는 ◀로 볼 수 있고, 여러 번 눌러도 빈 페이지가 쌓이지 않습니다. 노트북이 없으면 자동으로 만들어집니다. 폰에서는 상단의 오늘 N개(아직 체크하지 않은 오늘 일정 수, 다 하면 오늘 ✓)를 누르면 종이 아래의 오늘의 공부 목록으로 내려갑니다.
  4. 지난 내용을 훑어본 뒤 ▶ 화살표로 새 페이지를 만들고, 챕터 칸에 오늘 진도를 적고 필기를 시작합니다.
  5. 공부가 끝나면 목록의 체크박스를 눌러 완료 표시합니다.

구글 캘린더에서 일정 가져오기

구글 캘린더에 적어 둔 공부 일정을 오늘의 공부 목록과 달력으로 가져옵니다. 캘린더는 읽기만 하고, 앱에서 구글 캘린더로 쓰는 것은 없습니다.

  1. 설정 → 연동 → 구글 캘린더에서 구글 캘린더 연결을 누르고 Google 계정으로 허용합니다. 이름이 "공부"(또는 Study)인 캘린더가 있으면 그것이, 없으면 기본 캘린더가 가져올 캘린더로 골라집니다. 공부 일정만 따로 둔 캘린더를 쓰는 것을 권합니다.
  2. 지금 가져오기를 누르면 오늘부터 2주 동안의 일정이 한 번에 들어옵니다. 각 일정은 시작하는 날짜에 들어가므로 오늘 일정은 오늘의 공부 목록에, 그 뒤 일정은 달력에 보입니다. 반복 일정도 날짜별로 하나씩 들어오고, 오늘보다 먼저 시작해 오늘까지 이어지는 일정은 가져오지 않습니다.
  3. 과목은 일정 제목으로 정합니다: [economics] 3장 복습이나 economics: 3장 복습처럼 과목 이름으로 시작하면 그 과목(제목에서는 앞부분을 뗌), 제목 안에 과목 이름이 있으면 그 과목, 둘 다 아니면 기본 과목입니다. 유형은 그 과목의 노트북 유형을 따릅니다(없으면 lecture).
  4. 다시 가져오면 같은 일정은 두 번 들어오지 않고, 캘린더에서 바뀐 제목·날짜는 따라 바뀝니다. 단 앱에서 직접 고친 일정은 덮어쓰지 않고, 캘린더에서 지운 일정은 아직 체크하지 않았을 때만 지웁니다.

Google 로그인은 앱을 열어 둔 동안만 유지되므로, 새로 연 뒤 처음 가져올 때는 Google 확인 창이 한 번 뜹니다. 자동으로 가져오지는 않습니다(필요할 때 지금 가져오기).

자료실 사용하기

공부에 쓰는 모든 자료를 한 곳에서 관리합니다. 노트북과는 별개의 목록이므로, 노트를 쓰지 않은 자료도 자유롭게 등록할 수 있습니다. 등록 흐름은 "검색 한 번, 나머지는 확인만" 입니다 — 맨 위 검색창에 제목을 넣고 결과를 클릭하면 아래 필드가 자동으로 채워집니다.

  • 자동 채우기 — 유형을 고르고 제목을 검색하면 저자·출판사·표지 등이 채워집니다. 책(Google Books)·음악(MusicBrainz)·논문(Crossref)은 바로 되고, 영화/TV는 무료 TMDB 키를 설정 → 연동 → 자동 채우기에 넣으면 켜집니다(선택사항). 책 검색이 "Google Books 검색 한도에 도달했습니다"로 자주 막히면 같은 곳에 무료 Google Books API 키를 넣으세요(아래 FAQ). 직접 입력한 칸은 자동 채우기가 절대 덮어쓰지 않습니다.
  • 표지 — 표지 박스 하나가 전부입니다: 클릭하면 파일 선택, 이미지를 끌어다 놓거나, 복사한 이미지를 모달 안에서 Ctrl+V 하면 바로 들어갑니다(자동 압축). 박스 아래 ↻ 90°로 회전, 구글 이미지에서 표지 찾기로 표지를 찾을 수 있습니다.
  • 카테고리와 장르 — 카테고리는 자료의 형태(Novel, Documentary, Online Course...), 장르는 주제(Economics, History...)입니다. 같은 저자·시리즈("Write Right 2 - Beginner"와 "Write Right 3"도 같은 시리즈로 인식)의 자료를 추가하면 이전 분류·출판사를 빈 칸에 자동으로 이어받습니다. 드롭다운에 없는 값은 맨 아래 + 직접 입력…으로 그 자리에서 추가하고, 목록 정리(추가·이름 변경·합치기)는 설정 → 목록에서 합니다.

목록 탭 — 과목·카테고리·장르 관리

기기 간 동기화 (클라우드 동기화)

폰·태블릿·PC에서 같은 노트를 보려면 각 기기에서 설정 → 계정 → 클라우드 동기화 → Google로 로그인을 누르고 같은 Google 계정으로 로그인하세요. 그 뒤로는 한 기기에서 고친 내용이 몇 초 안에 다른 기기에 나타납니다.

  • 충돌 규칙: 같은 것을 두 기기에서 동시에 고치면 마지막 수정이 이깁니다. 서로 다른 노트북·페이지를 고친 경우에는 둘 다 반영됩니다.
  • 오프라인: 인터넷이 없어도 평소처럼 쓸 수 있고, 변경은 기기에 쌓였다가 연결되면 자동으로 올라갑니다. 사이드바 맨 아래 상태 표시가 동기화됨면 최신, 오프라인 · 연결되면 동기화면 대기 중입니다.
  • 처음 로그인할 때: 노트가 하나도 없던 새 기기는 클라우드의 노트를 그대로 받습니다(샘플 노트는 버립니다). 이미 노트가 있던 기기는 클라우드와 합쳐지고, 양쪽에 같은 노트가 있으면 더 최근에 고친 쪽이 남습니다.
  • 용량 제한: 한 페이지에 큰 이미지가 여러 장 들어가 약 900KB를 넘으면 그 페이지만 동기화되지 않고 이 기기에만 남습니다. 설정의 클라우드 동기화 카드에 빨간 글씨로 어떤 페이지인지 표시되니 이미지를 하나 줄이면 됩니다.
  • 받는 중인 페이지: 다른 기기에서 쓴 페이지의 내용이 아직 도착하지 않았으면 그 페이지에 "이 페이지는 아직 클라우드에서 받는 중입니다"가 뜨고 쓸 수 없습니다. 보통 몇 초 뒤 내용이 오면 저절로 풀립니다. 빈 자리에 먼저 쓰면 나중에 도착하는 원래 내용이 밀려 사라지기 때문입니다. 계속 풀리지 않으면(그 페이지가 위 용량 제한에 걸린 경우 등) 그래도 쓰기로 풀 수 있지만, 그때 쓴 내용이 다른 기기의 내용을 대신합니다.
  • 다른 계정으로 로그인하면: 이 브라우저의 노트가 전에 다른 Google 계정과 동기화된 것이면 "다른 계정의 노트가 있다"고 묻습니다. 확인하면 로컬 사본을 버리고 새 계정의 노트를 내려받고, 취소하면 로그아웃된 채 로컬 노트가 그대로 남습니다. 두 계정의 노트가 섞여 올라가는 일을 막기 위한 장치입니다.
  • 로그아웃해도 이 기기의 노트는 지워지지 않습니다. 전체 데이터 삭제는 로그인 중이면 이 기기의 사본만 지우고 새로고침 뒤 클라우드에서 다시 받아옵니다. 어디서나 지우려면 앱 안에서 노트북을 삭제하세요(삭제도 동기화됩니다).

What this app is for

Open it and start writing down what you just studied. Every screen and feature of StudyDesk is built and judged against that one sentence. A new feature or design change is measured by "does it cut the number of taps before the first letter?", and anything that does not (decoration, colour themes, and so on) waits.

  • The first screen is the paper — the app reopens on the page of the notebook you were last writing in (remembered per device). On a PC the caret is already in MAIN NOTES, so you just type; on a phone the paper comes first and the notebook list, today's list and the stat cards sit below it (the notebooks button in the top bar jumps down to the list). Backup and address notices dock at the bottom of the screen and never push the paper down.
  • Fewer hands — every keystroke is saved automatically, a new page gets today's date, text that overflows a page flows onto the next one, and go to note on a task opens today's page of its notebook in one tap.
  • Cornell notes as on paper — CUE (key questions) | MAIN NOTES (body) | SUMMARY, plus the self-test review step (hide the body, recall from the cues), laid out like the paper version.
  • Your data is yours — stored only in this browser by default, backups are plain JSON files, and cross-device sync is optional and goes only to your own account's space.

What is StudyDesk?

StudyDesk is a personal study-notes app built on the Cornell note-taking method. Lectures, reading, self-study and other activities are kept in notebooks per subject, and your study schedule is linked to those notebooks so that one click on "today's study list" continues your notes.

  • Nothing to install — it runs in the browser. No program to install, no account to create.
  • Data stays in your browser by default — unless you sign in, every note lives only in this browser (localStorage) and is sent nowhere. Signing in with a Google account under Settings → Account (cloud sync) copies them to a cloud space only you can read (Firebase) and keeps your devices in sync.
  • The writing flow is automated — a new page gets today's date, a page that overflows creates the next one, and the go to note button on a task opens that notebook on a page for today.

The pages

Notebooks
The main screen: the Cornell editor, the notebook list with search and filters, and today's study list. It opens on the page you were last writing in. (Details below.)
Library
A catalogue of what you study from (books, films, courses, papers, music…). Search a title to fill in the details, track status (want / in progress / done), progress and rating, and link an item to its notebook with go to note. (Details below.)
Calendar
A month view of recurring and one-off tasks. +N more on a day opens that day's full list with go to note buttons.
Schedule manager
Add and remove recurring tasks (by weekday) and one-off tasks (by date). Every task carries a subject and an activity type, which is how it finds its notebook. (Details below.)
Flashcards
Memory cards per subject, reviewed in review mode. Click a card to flip it; Esc or close leaves the review.
Settings
Six tabs. Backup (download backup / load backup, the reminder interval, storage usage, and at the bottom in a red frame clear all data) · Account (cloud sync between devices) · Display (font style handwritten / clean sans-serif, note text size, language) · Lists (subjects and the Library category / genre lists, see "The Lists tab" below) · Integrations (auto-fill keys, Google Calendar import) · Guide (this text). The last tab you opened is remembered. (See "Keeping your data" below.)

Writing Cornell notes in detail

One notebook holds "one activity of one subject". For the subject economics, lecture notes (lecture) and reading notes (book) are two different notebooks.

Fixed information — set once when the notebook is created
SUBJECT, TYPE (lecture / book / movie / project / self-study / other), TOPIC (the notebook's name)
Per-page information — changes each study day
chapter / subtitle (what the day covered), tags / keywords, the date (filled in automatically when a page is created). A page that continues the previous one (▶ on the last page, or overflow) inherits its chapter and tags; change or clear them as you like.

The body has the three Cornell areas: review questions and keywords in CUE on the left, the notes themselves in MAIN NOTES on the right, and the SUMMARY at the bottom.

  • Formatting — the toolbar above MAIN NOTES offers bold, italic, highlighter, text colour (black / red / blue), indent, labels, links and images. On phones only the frequent four (bold, highlighter, indent, image) show in one row; ⋯ at the right opens the rest (italic, colours, label, link) on a second row, remembered per device.
  • Markdown shortcuts — typing **bold**, *italic* or ==highlight== converts to formatting at once.
  • Images — pick a file with the image button, or paste a copied image with Ctrl+V. Large images are shrunk automatically to protect storage (longest side 1280px).
  • Turning pages — use the ◀ ▶ arrows beside the paper. On narrow screens (phone, split view) they move next to the page number (1 / 3) at the bottom so they never cover the paper. ▶ on the last page creates a new page, and notes that overflow a page create the next one automatically. A page filled on a PC may not fit a narrow screen; scroll inside MAIN NOTES to see the remaining lines (nothing is cut off). On phones the bar under the paper (◀ page ▶ · save) sticks to the bottom of the screen, so you can turn pages without scrolling even while the keyboard is up.
  • Jump to a page — click the page number (N / M) at the bottom to open the list of pages (chapter, date, preview) and jump straight to one. Pages with notes but an empty SUMMARY carry a no summary tag, and above the list N pages without a summary comes with an only these button, handy for the Cornell review step of going back to pages you have not summed up yet (blank pages are not tagged).
  • self-test (review mode) — the self-test button at the bottom (only an eye icon on narrow phones) blurs MAIN NOTES. Look only at the CUE questions and keywords and try to recall the content — the core review step of the Cornell method. show notes brings the text back.
  • Saving — everything is saved as you type. The save button only confirms the saved state.

Linking the schedule to notes (recommended workflow)

  1. Add a recurring task in Schedule manager, e.g. title "economics 101 lecture", subject economics, type lecture, Mon · Wed · Fri.
  2. On those days the task appears in today's study list on the Notebooks page.
  3. When you start studying, press go to note next to the task. The notebook for that subject and type opens on a page for today: the last page if it is already dated today or still blank, otherwise a new page after it dated today (chapter and tags carry over from the page before). Earlier notes are one ◀ away, and pressing it again never piles up empty pages. If there is no notebook yet, one is created. On a phone, today N at the top (today's tasks not yet checked off, today ✓ when all are done) scrolls down to today's study list below the paper.
  4. Skim the previous notes, create a new page with ▶, write today's chapter in the chapter field and start taking notes.
  5. When you are done, tick the checkbox in the list.

Importing from Google Calendar

Study events you keep in Google Calendar can be brought into today's study list and the Calendar. The calendar is only read; the app never writes to Google Calendar.

  1. Under Settings → Integrations → google calendar, press connect Google Calendar and allow access with your Google account. A calendar named "Study" (or 공부) is picked as which calendar if there is one, otherwise your main calendar. A calendar kept just for studying works best.
  2. import now brings in the events from today through the next two weeks. Each event goes on the day it starts, so today's show in today's study list and later ones in the Calendar. Each date of a repeating event comes in as its own task; an event that started before today and runs into it is not imported.
  3. The subject comes from the event title: one that starts with a subject name, like [economics] ch.3 review or economics: ch.3 review, goes to that subject (the prefix is dropped from the title); a title that contains a subject name goes to that subject; anything else goes to the default subject. The type follows that subject's notebook (lecture if it has none).
  4. Importing again never duplicates an event, and titles or dates changed in the calendar are followed. A task you edited in the app is never overwritten, and an event deleted from the calendar is removed only if it has not been checked off.

The Google sign-in lasts only while the app is open, so the first import after opening the app shows Google's confirmation window once. Nothing is imported automatically; press import now when you want to.

Using the Library

Keep everything you study from in one place. It is separate from the notebooks, so you can register material you never take notes on. The flow is "search once, then just confirm": type a title in the search box at the top, click a result, and the fields below fill themselves in.

  • Auto-fill — choose a type and search a title to fill in author, publisher, cover and so on. Books (Google Books), music (MusicBrainz) and papers (Crossref) work out of the box; films and TV switch on when you add a free TMDB key under Settings → Integrations → auto-fill (optional). If book search keeps stopping at "Google Books search limit reached", add a free Google Books API key in the same place (see the FAQ). Fields you typed yourself are never overwritten by auto-fill.
  • Cover — the cover box does everything: click to pick a file, drop an image onto it, or paste a copied image with Ctrl+V inside the dialog (compressed automatically). Below it, ↻ 90° rotates and search google images finds a cover.
  • Category and Genre — Category is the form of an item (Novel, Documentary, Online Course…), Genre is its subject (Economics, History…). Items of the same author or series ("Write Right 2 - Beginner" and "Write Right 3" count as one series) inherit the earlier classification and publisher into empty fields. A value missing from the dropdown can be added on the spot with + Custom… at the bottom; tidying the lists (add, rename, merge) happens under Settings → Lists.
  • Status and progress — enter only the essentials when adding; status (want / in progress / done), progress, rating and call number are managed in edit (the pencil button). Items in progress show a progress bar on their card.
  • Level — films take an age rating (Rated PG), courses and videos a difficulty (Beginner…), papers a year; a badge appears. Books and music have no level field.
  • Linking a notebook — go to note on a card lets you pick a subject and create or open that item's notebook. Delete is the Delete button at the bottom left of the edit dialog.
  • Bulk edit — tick several cards and a bulk edit bar appears at the top to change Category / Genre / status for all of them at once.

The Lists tab — subjects, categories, genres

Settings → Lists is where the app's pick lists are managed in one place.

  • subjects — add, rename and delete subjects. Each row shows how many notebooks, tasks and cards use it. Deleting a subject that is in use first asks which subject to move everything to, moves the notebooks, tasks and cards there, and then deletes it (this is also how two subjects are merged). At least one subject must remain, so the last one cannot be deleted, and the same name (ignoring case) cannot be added twice.
  • library categories / genres — the values your Library items use plus the ones you added yourself (marked CUSTOM), each with its usage count. The built-in values (Novel, History and about 60 others) are not listed; they stay in the dropdowns. A value added with + category / + genre appears in the Library dropdowns before any item uses it. Renaming applies to every item using that value at once, so use it to merge two spellings ("Sci-fi" → "Science Fiction"). Values in use have no delete button (merge them by renaming); only unused custom values can be removed.
  • All of this is ordinary data: it goes into backup files and, with cloud sync on, to your other devices.

Keeping your data — please read

All data (notes, tasks, cards, images) is stored only in the browser you are using right now. It disappears or is not visible in these cases:

  • Clearing the browser's browsing data (cookies, site data) deletes every note, and it cannot be recovered.
  • Without signing in, another browser (e.g. Chrome ↔ Edge) or another computer or phone starts empty. To see the same notes on several devices, turn on "cloud sync" below; for a one-off move, a backup file also works.
  • In a private / incognito window the data is gone the moment the window closes.
  • Download a backup file (JSON) regularly with Settings → Backup → download backup. It is the only way to restore with load backup after data loss, and the way to move notes to another browser or computer.
  • When the last backup is older than the chosen interval, a reminder appears at the bottom of the screen. backup now downloads one immediately; the interval is set under Settings → Backup → remind me to back up (3 · 7 · 14 · 30 days or never). It does not show while only the sample notes are present (they are not yours).
  • Storage is limited to a few MB per browser. Pasting dozens of large screenshots can make saving fail.

Installing on a phone or tablet

StudyDesk is an installable web app (PWA). It installs straight from the browser without an app store, opens full-screen from a home-screen icon, and opens without internet.

  1. Open https://amber-studydesk.netlify.app/ in the phone's browser. (The address changed on 4 November 2026, see "The address change" above.)
  2. Android (Chrome): menu (⋮) at the top right → Install app or Add to Home screen.
  3. iPhone / iPad (Safari): share button (□↑) at the bottom → Add to Home Screen. (iOS installs only from Safari.) Note: on iPhone the home-screen app and Safari use separate storage. If you already have notes in Safari, download a backup there with Settings → Backup → download backup first, then open the installed app and load it with Settings → Backup → load backup. It does not carry over by itself.
  4. PC (Chrome / Edge): the install icon at the right of the address bar opens it as a single-window app.
  • Open the app once while online right after installing. The offline files are saved then; from that point it opens without internet. Installing and opening it straight away in flight mode can show a blank screen.
  • With internet, the installed app fetches the latest version each time it opens. If an old screen shows, close the app completely and open it again.
  • If you have a StudyDesk app installed from the old address (amber67-git.github.io/studydesk), move your notes as described under "The address change" and then delete it.
  • Library auto-fill (book and film search) needs internet. Notes, schedule and cards all work offline.
  • To see the same notes on phone and PC, sign in with the same Google account under Settings → Account → cloud sync (see "Cloud sync" below). Devices that are not signed in store only in their own browser.

Cloud sync

To see the same notes on phone, tablet and PC, press Settings → Account → cloud sync → sign in with Google on each device and sign in with the same Google account. From then on a change on one device appears on the others within seconds.

  • Conflicts: if the same thing is edited on two devices at once, the latest edit wins. Edits to different notebooks or pages are both kept.
  • Offline: everything works as usual without internet; changes queue on the device and upload when the connection returns. The status at the bottom of the sidebar reads synced when up to date and offline · will sync while waiting.
  • First sign-in: a new device with no notes takes the cloud notes as they are (sample notes are dropped). A device that already has notes is merged with the cloud; where both have the same note, the more recently edited copy stays.
  • Size limit: a page with several large images above about 900 KB is not synced and stays on this device only. The cloud sync card in Settings names the page in red; remove one image and it syncs.
  • Pages still arriving: when the content of a page written on another device has not arrived yet, that page shows "this page is still downloading from the cloud" and cannot be written on. It unlocks by itself when the content arrives, usually within seconds. Writing into the empty spot first would push the real content out when it lands. If it never unlocks (for example the page is over the size limit above), edit anyway unlocks it, but what you write then replaces the other device's version.
  • Signing in with another account: if this browser's notes were synced with a different Google account, the app asks about it. OK discards the local copy and downloads the new account's notes; Cancel signs out and leaves the local notes alone. This prevents two accounts' notes from being mixed.
  • Signing out does not delete the notes on this device. clear all data while signed in clears only this device's copy and downloads from the cloud again after the reload. To delete everywhere, delete the notebook inside the app (deletions sync too).

FAQ

Display

Some formatting buttons (bold, colours…) are missing.
In older versions the toolbar scrolled sideways on narrow windows and hid the link and image buttons off-screen. Now, on narrow paper (phones), only the frequent four (bold, highlighter, indent, image) are in one row; italic, colours, label and link appear on a second row when you press ⋯ (more formatting) at the right end of the toolbar. The open state is remembered on this device. If the buttons are still missing after pressing ⋯, or there is no ⋯ at all, you are looking at an old copy of the screen: reload the page (an installed app: close it completely and open it again).
Icons show as empty squares.
An old-version problem that appeared when the external icon font was blocked. The current version embeds its icons, so they always show, even offline. If you see this, you are opening old files; replace them with the latest.
Changes made on the phone do not show on the PC.
Check that both devices are signed in with the same Google account under Settings → Account → cloud sync and that the bottom of the sidebar reads synced. offline · will sync uploads automatically once online. A device that is not signed in stores only in its own browser. If the cloud sync card in Settings shows "over the 900 KB per-page limit" in red, that page has too many images and is left out of sync.

Installing

Installing says "This app is already installed", and tapping it says "Could not open app".
This happens when another app is already installed from the same site address. Current Android Chrome installs only one app per site address (e.g. amber67-git.github.io), reported as a Chrome bug. It happened at the old address on 4 November 2026 (ClassDesk installed blocked StudyDesk and vice versa), which is why StudyDesk moved to its new address (amber-studydesk.netlify.app). Changing the app id or scope did not fix it. Typing chrome://webapks in Chrome's address bar lists installed apps with their addresses. Installing from the new address works alongside ClassDesk. If a StudyDesk app from the old address is still installed, move your notes as described under "The address change" and then delete it. Do not press Chrome's clear data or clear site data: that erases the notes too.

Data

All of yesterday's notes are gone.
First check (1) that it is the same browser, (2) that it is not a private window, (3) whether browser data was cleared recently. Another browser having no data is normal. With a backup file, restore under Settings → Backup → load backup. Browser data cleared without a backup cannot be recovered.
Saving is slow or fails after pasting images.
Most likely the browser's storage limit (a few MB) is near. A failed save shows "save failed — storage full" with an explanation. Current usage is shown in the Settings → Backup tab; delete large images and edit again to save. (Large images are shrunk automatically, but dozens of them still reach the limit.)
It says "not saving — this browser is blocking storage".
You are in a private window or the browser is blocking site data. Nothing you write is saved in this state. Open the app in a normal window. If you already wrote something, download it first with Settings → Backup → download backup before closing the tab.
Loading a backup says "that backup could not be loaded".
The file is damaged or is not this app's backup format. Your existing notes are kept and not overwritten. Try another backup file.
Searching a film in the Library asks for a key.
Only film and TV auto-fill needs a free TMDB key (books, music and papers work without one). Sign up at themoviedb.org, get a key from the API section of the settings there, and paste it under Settings → Integrations → auto-fill. "the API key was rejected" means the key was pasted wrongly. Everything can also be typed in by hand without a key.
Library search keeps failing.
Check the internet connection first. Offline, or when a response takes more than 15 seconds, the search stops and says so. Many searches in a short time can show "search limit reached"; try again a few minutes later. Every item can be registered by hand even when search fails.
Book search says "Google Books search limit reached".
Google Books without a key shares its limit among many users, so it can run out often. With your own key you get 1,000 free searches a day to yourself. To get one: create a project at console.cloud.google.com → enable the Books API → under Credentials, create an API key → paste it into the Google Books API key field under Settings → Integrations → auto-fill. Restricting the key to the website amber-studydesk.netlify.app and to the Books API keeps it safe. "the API key was rejected" means the key was pasted wrongly or the Books API is not enabled. "your Google Books key has used up its quota" means your key's daily quota is spent; it resets at midnight Pacific time. The key is stored on this device and in backup files (and in your cloud when sync is on), so do not hand backup files to others.
The google calendar card says "calendar import is not set up yet".
Whoever deploys the app has to add a Google OAuth client ID once. At console.cloud.google.com (the project of the Books API key works too), enable the Google Calendar API → set up the OAuth consent screen (External, left in testing, with your own Google account added as a test user) → under Credentials, create an OAuth client ID (Web application) with https://amber-studydesk.netlify.app as an authorized JavaScript origin. Put that client ID into GOOGLE_CLIENT_ID at the top of app.js and deploy. If connecting says "sign-in was cancelled or access was not allowed", check that your account is listed as a test user.

Editing

I typed a chapter, turned the page and back, and it was gone.
A saving bug of an old version. The current version saves every field, chapter and tags included, immediately. Make sure you have the latest files.
Nothing happens when I press the colour or highlighter buttons.
Select the text to colour by dragging first, then press the button. Pressing without a selection shows a "select text first" message.
(When editing the files yourself) I renamed a menu but the page title stayed the same.
A menu label lives in three places: the English text in index.html, its key in the string table in app.js (I18N, English and Korean columns), and PAGE_TITLES for the page title. When changing English wording, change index.html and the table's English column identically, or that spot stops being translated. Leave the internal name inside showPage('...') alone or the page stops opening.
